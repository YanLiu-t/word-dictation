# 单词听写音频制作 SOP

> 本文件是这套流程的唯一规范。任何与本文件冲突的做法，以本文件为准。
> 版本：v1.0　适用范围：手写或印刷的英语单词笔记照片 → 分页词表 → 听写音频

---

## 1. 产出物

一次「批次」的标准产出，固定为四件：

| 文件 | 说明 | 是否入库 |
|---|---|---|
| `<批次名>_读一遍.mp3` | 英文 → 中文，每个词只读一遍 | 否 |
| `<批次名>_读两遍.mp3` | 英文 → 中文 → 英文 → 中文 | 否 |
| `<批次名>_脚本.txt` | 纯朗读脚本，可直接复制 | 否 |
| `wordlist.tsv` | 词表，唯一事实来源 | 是 |

`<批次名>` 由用户指定，例如 `10页`。不带批次名时默认用日期，如 `20261119`。

---

## 2. 目录约定

```text
批次目录/
├── input/            原始照片，按 01.jpg、02.jpg…命名
├── ocr/              模型原始识别结果（JSON，一页一个）
├── wordlist.tsv      ★ 唯一事实来源
├── report.md         处理报告
└── out/              音频与脚本输出
```

照片命名决定处理顺序，必须用两位数前缀（`01`、`02`… `10`），保证自然排序与人工顺序一致。

---

## 3. 六步流程

### 第 1 步：拍照

| 项目 | 要求 |
|---|---|
| 一页一张 | 不要一页拍两半，也不要把两页压成一张 |
| 光线 | 均匀、无阴影压住字迹 |
| 角度 | 尽量垂直俯拍，避免梯形变形 |
| 清晰度 | 单词拼写的每个字母都可辨认 |

照片不合格时**重拍**，不要让识别环节去补救。

### 第 2 步：识别

- 识别 Prompt 固定使用 [`prompts/extract.md`](../prompts/extract.md)，不得临时改字段
- 一页一次请求，结果原样存入 `ocr/pNN.json`
- 模型需支持图像输入；免费额度服务见第 7 节
- 默认把整页上下切成两块分别识别（`ocr.tiles`），减少整行漏读
- 默认先做图像预处理（`ocr.preprocess`）：按 EXIF 摆正、自动对比度、轻锐化、长边放大到 1800 像素
- 默认开启交叉校验（`ocr.cross_check`）：用第二个模型再识别一遍整页，第二遍多看到的词（第一遍可能漏了）标记「仅第二遍识别到」，交由第 4 步人工确认；第一遍有、第二遍没有的词不拦（第二遍模型较弱，漏读属正常）

**验收**：每页条目数与照片实际行数一致，无整行漏读。

### 第 3 步：对齐校验（自动）

执行 `dictation check`，按第 5 节规则 R1–R8 处理。输出 `wordlist.tsv` 与 `report.md`。

随后执行 `dictation verify` 做释义反查：用纯文本模型检查「单词 ↔ 释义」是否匹配，把 `bank`+「树皮」改成 `bark`、`major`+「镇长」改成 `mayor`。约束：

- 修正词与原词编辑距离不得超过 2（超出视为不同词，只记备注）
- 同一词根的不同词形不改（`relentlessly` / `relentless` 不算误读）
- 给不出可信候选时只写备注，不改词、不改状态

**验收**：`review` 条数不超过总数的 20%。交叉校验会主动把「仅第二遍识别到」「释义含数字」「手写释义与常见义偏差大」的条目转成 `review`，条数偏多是正常的；若超过 20%，说明照片质量或模型限流有问题，回退第 1 步。

### 第 4 步：人工核对（必须做）

只核对 `status != ok` 的行，逐条确认：

- `review`：确认单词拼写与释义，改完把 `status` 改为 `ok`
- `dup`：确认是否真的重复，是则保持 `dup`
- 释义列：可自由修改，但必须保留 2–3 个高频义项，不要堆砌生僻义

**这一步不通过，不允许进入第 5 步。**

### 第 5 步：合成语音

执行 `dictation build`。

- 语音片段按 `哈希(文本+音色+语速)` 缓存，改一个词只重合成那一个片段
- 实际朗读的单词取自 `word` 列，读音修正按第 6 节映射表
- 实际朗读的释义取自 `meaning` 列，`status != ok` 的行默认跳过

### 第 6 步：拼接与报告

按第 6 节的节奏拼接，生成四件产出物，`report.md` 记录：

- 总条目数、实际朗读数
- 跳过的条目及原因
- 读音修正过的词
- 中文释义被纠正过的词及差异

## 4. 词表格式 `wordlist.tsv`

制表符分隔，UTF-8 无 BOM，首行为表头：

| 列 | 必填 | 说明 |
|---|---|---|
| `seq` | 是 | 序号，从 1 连续 |
| `word` | 是 | 英文单词，全小写；短语用连字符，如 `well-being` |
| `meaning` | 是 | 中文释义，多义用「，」分隔 |
| `note` | 否 | 中文备注：释义纠偏、拼写判定依据等 |
| `status` | 是 | `ok` / `review` / `dup` / `skip` |
| `source` | 否 | 来源页，如 `p03` |

`status` 取值：

- `ok` — 进音频
- `review` — 待人工确认，**不进音频**
- `dup` — 与前面重复，**不进音频**
- `skip` — 用户明确不要，**不进音频**

示例：

```text
seq	word	meaning	note	status	source
1	century	世纪			ok	p01
236	resume	继续，重新开始	动词"继续"，读 ri-ZOOM	ok	p06
292	rape	强奸，强奸罪	字迹像 rope，按释义判定为 rape	ok	p07
447	strand	股，缕，方面			ok	p10
```

## 5. 校验规则

| 编号 | 规则 |
|---|---|
| **R1** | **顺序**：同页从上到下、从左到右；多列排版时按列块整体读取，不跨列穿插；跨页按文件名排序 |
| **R2** | **忽略干扰**：词性标注（n. / v. / a. / ad.）、红笔划线、波浪线、箭头、页码、页边批注，一律不进词表 |
| **R3** | **一级反查**：拼写置信度 < 0.9 时，用释义在 CET-4/6 词表中反查候选；候选唯一则采用，`note` 记「字迹像 X，按释义判定为 Y」，`status=ok` |
| **R4** | **二级反查**：拼写与释义都存疑时，仅当候选唯一且为高频常用词才采用，`status=review` 交人工 |
| **R5** | **禁止编造**：无候选、或候选多于一个且无法用释义排除时，`word` 留空并置 `status=review`，**不得猜一个填进去** |
| **R6** | **去重**：同一单词出现多次，保留首次出现，后续置 `status=dup` |
| **R7** | **释义纠偏**：手写释义与词义明显不符时（例：`unwavering` 写成"万无一失的"），以词义为准写入 `meaning`，原写法记入 `note` |
| **R8** | **音频排除**：`status ∈ {review, dup, skip}` 的行不进入任何音频 |

**释义写法**：以「高频核心义」为主，最多 3 个义项，用「，」分隔。不写词性，不写例句，不写搭配。

## 6. 音频规范

### 节奏

```text
读两遍：英文 → 中文 → 英文 → 中文
读一遍：英文 → 中文
```

### 停顿

| 位置 | 时长 |
|---|---|
| 英文与中文之间 | 200 ms |
| 两遍之间（仅读两遍版） | 450 ms |
| 词与词之间 | 900 ms |

### 语音

| 语言 | 后端 | 音色 | 语速 |
|---|---|---|---|
| 英文 | edge（当前版本默认） | `en-US-AriaNeural` | -15% |
| 中文 | edge（当前版本默认） | `zh-CN-XiaoxiaoNeural` | -10% |
| 英文 | piper（规划中，离线） | `en_US-lessac-medium` | 默认 |
| 中文 | piper（规划中，离线） | `zh_CN-huayan-medium` | 默认 |

`edge` 音质好但调用的是微软非官方接口，仅适合本机自用。v1 只提供 `edge` 后端；对外批量分发前应先补上离线后端，`--backend` 参数已预留。

### 读音修正

英式拼写按实际读音朗读，其余按原词读：

| 词表写法 | 朗读 |
|---|---|
| `plough` | plow |
| `tyre` | tire |
| `odour` | odor |
| `splendour` | splendor |

带连字符的词（`well-being`、`have-nots`、`wide-brimmed`）按两个词连读，不读连字符。

`resume` 作动词读 ri-ZOOM，需在 `note` 中标注，合成时按标注处理。

## 7. 识别服务与 API Key

### Key 的管理方式

- Key **只存本地**，写在项目根目录的 `.env`，且 `.env` 已加入 `.gitignore`
- 网页版提供「设置 Key」面板：粘贴 → 保存到本机 → 点「测试连接」验证可用
- **任何情况下不要把 Key 写进代码、提交到仓库、或贴进 issue**

### 免费额度服务

| 服务 | 定位 | 备注 |
|---|---|---|
| 智谱 GLM-4V-Flash | 首选 | 中文手写与中文释义识别最稳 |
| Google Gemini Flash | 兜底 | 英文识别准，免费额度较大 |
| 通义 Qwen-VL | 备选 | 新用户有免费额度 |

各家免费额度与限流会随时调整，以官网当前说明为准。一个 10 页批次约需 10 次请求，正常复习用量远低于任何一家的免费额度。

### 实测准确率（3 页手写笔记，136 个词）

| 方案 | 识别条数 | 结论 |
|---|---|---|
| 免费 `glm-4.6v-flash` + 分块 + 交叉校验 | 139 | 召回最好，仍有 4–6 处硬伤：`grand→strand`、`comb→amb`、`mating→matting`、`publicize→pubilcize` |
| 付费 `glm-4v-plus` | 127 | 漏约 10 个词，臆造原文没有的 `tenet`，误读 `bark→bank`、`jargon→sargon`、`sake→soke` |

结论：**免费额度模型在密集手写体上确实吃力，但付费模型也不等于可靠。** 本次实测中付费模型并没有更准，反而漏词更多；免费模型的另一个风险是高峰限流（HTTP 429），会自动降级到更弱的 `glm-4v-flash`，识别质量随之下降。

因此：

- 想要更稳的召回，优先用免费链 + 分块 + 交叉校验，再人工核对；
- 需要换模型对比时，用 `dictation extract <批次> --model glm-4v-plus` 指定付费模型；
- 无论用哪个模型，都必须执行第 4 步人工核对；
- 觉得交叉校验噪音太大可加 `--no-cross` 关闭，但此时 `review` 会明显减少、误读更容易漏进音频，**不推荐**。

### 没有 Key 时的降级路径

`provider=manual`：跳过自动识别，由使用者把图片交给任意支持读图的 AI，用 `prompts/extract.md` 取得 JSON，手工放入 `ocr/` 目录。后续校验、合成、拼接完全不变。

## 8. 质量红线

1. **宁可少一个词，不可错一个词。** 拼写、释义、读音三者任一存疑，宁可 `review` 跳过。
2. **不编造。** 释义可以补全，单词不可以猜。
3. **词表优先于音频。** 音频永远是词表的派生物，改内容只改词表，然后重新 build。
4. **人工核对不可省略。** 自动化只能降低工作量，不能替代确认。

## 9. 附：本标准形成过程中修正过的典型问题

留作校准样本，供后续判断参考。

| 现象 | 正确处理 |
|---|---|
| 字迹像 `strand`，释义写「宏大的」 | 释义只对应 `grand` → 判为 `grand` |
| 字迹像 `fore`，释义写「进展」 | 只有 `fare` 有「进展」义 → 判为 `fare` |
| `bark` 被读成 `bank`、`comb` 读成 `amb` | 形近字母误读，交给审阅或让模型给候选 |
| 两个模型分别读成 `mating` / `matting` | 两遍不一致 → `review`，人工按释义「交配」判定为 `mating` |
| 两个模型分别读成 `jargon` / `sargon`、`sake` / `soke` | 同上，词典里只有前者 → 判为 `jargon`、`sake` |
| 原文没有 `tenet`，模型却输出了 | 臆造词，核对页数与行数后删除，不得进音频 |
| 释义出现 `033(注意力)` | 识别串行（应为「吸引（注意力）」），按数字规则转 `review` |
| 字迹像 `rope`，释义写「强奸」 | 判为 `rape`，`note` 记录 |
| 字迹像 `clinically`，释义写「爱嘲笑地」 | 判为 `cynically` |
| `unwavering` 释义写成「万无一失的」 | 以词义为准改「坚定不移的」，原写法入 `note` |
| `material` 释义写成「大批的、广泛的」 | 与 `massive` 混淆，按 `material` 核心义「物质的，材料」 |
| `conduct` 释义写成「经营方式」 | 名词核心义为「行为，举止」 |
| `seize`、`sturdy` 两页都出现 | 保留首次，后续 `dup`，音频只读一次 |
| 同一行里 `convenient` 与 `conventional` 并写 | 拆为两条独立词条 |
